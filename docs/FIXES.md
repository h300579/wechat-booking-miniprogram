# 已知缺陷修复（2026-09-11）

> 本文是历史修复记录，52 项测试及未部署描述对应当次工作。最新功能、59 项测试和开发环境部署状态见 [项目状态](STATUS.md)。

本次修复针对结构审查确认的问题，不包含云端部署、真实门店配置或生产初始化。

| 问题                                          | 修复后的行为                                                                                     |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 我的预约加载更多时切换标签，第一页丢失        | 刷新作废旧响应，待旧请求结束后重新获取第一页；旧错误和加载状态也不会覆盖新请求                   |
| 列表把 99.50 显示为 100                       | 所有金额统一保留两位小数                                                                         |
| 修改配置不改变页面日期、店名或示例标记        | 构建从指定配置生成公开数据；进入选择页时计算日期范围，按阶段显示示例标记，预约配额提示读取配置   |
| 每个页面内嵌一份 API 工具，去重状态不共享     | 前端改为普通 CommonJS 模块编译；只由构建脚本编译 TypeScript，开发工具插件不再重复编译            |
| 每类过期记录只删 50 条                        | 有界分批清理，默认最多 500 条／软时限 45 秒，明确报告积压和未完成原因；新增 cloud:cleanup 子命令 |
| 对账漏掉残留的用户配额                        | 补用户配额到预约的反向核验、重复／错归属／错时间／取消检查；分页扫描，超时或超量不会报告通过     |
| 费用漏填、任意八个 true 标记也能通过上线检查  | 必要字符串、有限数值、固定八项证据名称均严格检查                                                 |
| 更新函数代码后超时与环境变量仍旧              | 部署代码后单独更新配置、等待就绪并回读核验；保留其他环境变量；运行时不匹配时提前停止             |
| 两条部署路径生成不同超时                      | 构建和部署共享 infra/functions.json：booking 5 秒，operations 60 秒                              |
| 临时 setup 的诊断和 settings 入口绕过关闭标记 | 删除身份诊断分支；settings 规则入口也受关闭标记限制。仅修改本地代码，未部署                      |
