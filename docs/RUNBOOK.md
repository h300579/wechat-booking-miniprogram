# 上线、预算与故障处理

## 上线门禁

复制 `config/production.example.json` 到负责人维护的生产配置。填写真实门店资料、独立环境 ID、套餐费用 B、资源额度 Q、独立收费项、告警接收人和事故负责人。50%/80%/90%、超额关闭、限流、恢复和真机验证必须有真实证据；`npm run release:check` 对未完成项拒绝通过。不要把手工将 evidence 改成 true 当成实际验收。

不得自动购买、续订、升级或打开超额按量。开发环境显示免费不代表所有独立收费项免费。负责人必须确认停服可以接受，并核对套餐额度耗尽时的实际行为。

## 资源告警

50%：检查趋势与月底预测。
80%：核查异常账号、接口和图片；暂停非必要批处理与上传。
90%：关闭新预约与上传，保留查询和取消的剩余额度。
平台上限：按实际停服行为处理，用户显示小程序内置维护提示。

`server/budget.ts` 是去重阈值与维护开关实现。`scripts/budget.ts` 读取受控监控采样 `{used,quota,period}`，新阈值返回退出码 2；须由负责人配置的调度器连接实际监控来源和邮件/短信通知。代码不伪造平台采样或通知成功。5 分钟调用或下载较基线超过 3 倍需要在平台监控配置。无历史基线用明确全局阈值。

告警有延迟，不是硬预算上限。云函数中的拒绝本身消耗调用/数据库额度；公共文件下载不经过预约限流。真正停损依赖平台额度、超额关闭和必要时停用函数入口/文件分发。禁止用删除数据库止损。

## 备份恢复

每日使用套餐支持的备份/导出。目标 RPO 24 小时、RTO 4 小时，实际达到与否需演练。受控脚本备份必须先关闭新预约，再在平台暂停所有预约写入（包括取消）；确认后设置 BOOKING_WRITES_STOPPED=yes，运行 cloud:backup。否则跨集合导出不保证一致性。

恢复到隔离环境，不直接覆盖线上：导入全部集合及其固定 ID，应用相同规则与索引，保持预约入口关闭。运行 cloud:reconcile，核对 appointments、resource_days、users.futureAppointments、idempotency_records。抽样核对预约人归属、金额时长快照、取消状态；当前 reconcile 仅覆盖预约窗口及全体用户未来配额：必须 complete=true 且 ok=true，并另做历史预约、取消与幂等记录的完整恢复核验，之后再按负责人流程切换。恢复后按当前日期补齐日程，再恢复接单。

告警失效或资源耗尽时，负责人通过已登记联系方式处理；获取最新导出核对人工预约，避免线下与线上重复分配同一资源时间。生产日志不得包含原始 event、OPENID、凭证；默认保留 7 天，审计与备份按明确保留策略计费。

## 当前不能直接确认的项目

实际云端多实例事务、SDK 兼容、索引和规则生效、平台入口限流、告警送达、费用封顶行为、定时任务、备份恢复、生产环境及真实门店资料。这些必须实测，不能以本地测试替代。

清理任务应独立于每日日程生成运行，初始每 15 分钟一批；监控 backlog/complete/stopReason，未扫描的集合 hasMore=null 也按未完成处理。不要因一次达到 500 条或 45 秒上限就忽略告警，也不要改成无限循环。
